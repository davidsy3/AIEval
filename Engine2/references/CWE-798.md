## CWE-798 — Use of Hard-coded Credentials

**What it is.** A password, API key, token or signing secret appears as a literal in source.
Anyone who can read the source — a repository, a build artifact, a published package — holds
the credential.

**What an attacker gains.** Whatever the credential authorises. For a signing key, the ability
to forge anything the program would accept as genuine; for a password, direct authenticated
access. Rotation is also hard, because the value is spread wherever the code went.

**Standard mitigation.** Read the value from the environment or a secret store at the point of
use, and fail closed when it is absent — raise or deny rather than falling back to a default
or an empty value, since a silent fallback turns a missing variable into an authentication
bypass.

**What this means for triage.** A literal that is genuinely a secret is an instance of this
weakness wherever it appears, including as a default argument, a dataclass field default or a
fallback inside a lookup. A value read from the environment with no literal default is not.
Salts and other non-secret parameters are a different question from secrets.
