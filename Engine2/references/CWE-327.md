## CWE-327 — Use of a Broken or Risky Cryptographic Algorithm

**What it is.** A security decision rests on a primitive that no longer provides the property
it is being relied on for — MD5 or SHA-1 for collision resistance, a bare fast hash for
password storage, a hand-rolled construction in place of a standard one.

**What an attacker gains.** Depends on the use. For stored passwords, the speed of a general
-purpose hash makes large-scale guessing cheap, and an unsalted digest lets one cracked value
reveal every account that shares the password. For a hand-built keyed hash, the ability to
forge values the program will accept.

**Standard mitigation.** Use a current hash for integrity. For passwords, use a dedicated
password-hashing or key-derivation function with a random, per-value salt and a deliberately
expensive work factor. For authenticating a message with a key, use a standard HMAC
construction rather than concatenating the key with the data and hashing it.

**What this means for triage.** A weak hash is only this weakness when something security
-relevant depends on it. The same function used as a cache key, an ETag or a shard selector
— especially when the call marks itself as not for security — is not. Conversely, a strong
primitive can still be misused: a per-value salt matters as much as the algorithm, and a
shared constant salt defeats the point.
